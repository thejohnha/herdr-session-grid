# The grid — one picker for every herdr workspace and tab

`hg` (or `hg go`) from any terminal on this Mac goes to it — creating the `herdr sessions` workspace at position 0
with its single tab if missing. The tab is named for the herdr session the grid represents — `default` here — because a grid instance talks to one socket and so shows one herdr session; a second herdr session would get a second tab named for it, which is what the workspace name says. Not bare `sessions`: a bare "session" is an AI conversation in `CONTEXT.md`. From inside herdr, `ctrl+alt+1` (one chord, no prefix) or `ctrl+b` then `shift+1` jumps there — `switch_workspace` is bound to both, herdr rejects a `0..9` range, and the grid workspace is always first. relaunching the grid there if its pane is back at a shell (a herdr restart leaves
it so), and focusing it. `hg` alone runs the grid in the current pane. Vocabulary (cell, parked, open/park/forget)
is in `CONTEXT.md`. Why: John keeps many sessions he means to return to; each live one costs
~170 MB and CPU, and 92 tabs to 67 was a felt improvement. The grid keeps everything reachable
while few things run.

- Cell states: herdr's glyphs for a live session (● working, ○ idle, ● done, ● blocked); `◌` stopped — the tab is open but no session runs in it, and `~/.claude/state/state_claude_session_herdr_tabs.json` (what `hr` reads) says which session it last held, so Enter resumes that session INTO that tab, never a new one; `P` parked — no tab; `·` a tab that never held a session.
- A closed workspace keeps its row while any of its cells is parked. Opening one recreates the workspace under a new id with the stored label, at the row's position among the workspaces herdr still has, resumes into its root pane, and re-keys the row.
- Enter on a live cell goes to its tab. Enter on a stopped or parked cell brings the session back and STAYS in the grid — a second Enter goes there — so several can be woken and then one chosen.
- Keys: arrows move · Enter open · `b` bookmark · Tab next bookmark · `p` park · `x` forget (parked only) · `m` grab, arrows carry, `m`/Enter drop, Esc cancel · `r` rename the tab label · `=` push the grid's order onto herdr · `R` refresh · `?` every key with one line each · `q` quit.
- The detail panel colors follow the statusline's meanings: label bold, title plain, the status WORD in the cell's own status color with the pane plain, the session id dim (as the statusline dims it) and the account after it (`personal` when the account sidecar has no row), size in the statusline's cornflower blue (xterm 111), `Cx` = the session's context tokens read off the last assistant record of its transcript (the same sum the statusline shows and the auto-successor cron thresholds on) in the statusline's tiers — green under 150k, yellow to 200k, red past — and `★ bookmarked` in the picker's gold (xterm 220). Parked `P` and stopped `◌` cells draw in the same cornflower (xterm 111) and cells waiting for input (● done, ○ idle) in pure green (xterm 46), working cells in pure yellow (xterm 226), the terminal's basic yellow having read dull, both chosen by John from field tests of stars in one color scattered among the other: the theme's mint green and the paler blues blurred together, and the terminal's basic blue read as navy across a mostly-parked grid. Under 256 colors the basic blue/green/yellow/red stand in. Title lines wrap at the panel edge rather than truncate.
- Throwaway sessions (`ci`/`cii`) never become cells: the tab-recording hook `record-herdr-tab.sh` skips a session whose config dir carries the `.ci-priv` tag, because its transcript is wiped on exit and a cell for it could never be woken (one such ghost, labeled `ci`, was forgotten by hand on 2026-09-16).
- `herdr_session_grid.py run --demo` draws the real grid with every name replaced — workspaces as example names (bookkeeping, taxes, website …), tab labels `task NN`, titles, ids, accounts and prime directives as stand-ins — and writes nothing and reorders nothing, so a screenshot of it can be shared. Statuses, bookmarks, sizes and context counts stay real.
- Workspaces labeled `selftest …` are never recorded: the session-manager selftest builds them and tears them down, and their tabs would otherwise outlive it as parked cells (two such rows had to be dropped by hand). `IGNORE_WS` in the script holds the prefix list.
- Bookmarks: `b` marks the cell and it draws as `★` in place of its dot — `☆` when the dot is hollow, so an idle cell stays telling — keeping the status color (yellow working, green waiting for input) — except a parked cell's star, which draws in a lighter blue (xterm 123) than the parked `P`s around it so bookmarks stand out across a mostly-parked row, John's pick from a twelve-blue field test; Tab jumps to the next `★`, wrapping; the header counts them. The flag lives on the CELL in the grid's own file, not in the session's title — so it survives a park, a successor (the cell follows the lineage) and a merge, and it never appends a title record to a live session, which the session's next prompt would outvote. A session whose title already carries the picker's `⭐` (ch-pick Alt-') draws as `★` too, read-only: `b` on one of those points at Alt-' rather than writing a second marker. Esc never quits: it only cancels a grab, so a reflex Esc cannot drop you to a shell.
- `p`, `x` and `=` ask `y/n` first: park costs a resume to undo and stops the session's background work (its watches and monitors — `quit` answers Claude Code's exit menu with *exit and stop tasks*, see `cli-claude-sessions.md`), forget has no undo key, and `=` moves real tabs. Enter does not ask — opening is the point.
- `hg` types into the grid's pane only when the pane's foreground is its own shell and nothing else; a running grid, anything else in the foreground, or an unreadable process list all get nothing sent, because text sent into the running grid lands on its keys.
- File: `~/.claude/state/state_claude_session_grid.json` — row order, and per workspace the ordered cells. Live cells are rewritten from herdr on every refresh (3 s while open); only parked cells, order and labels are authoritative here. Delete it and the next run re-seeds from herdr with nothing parked.
- Backed up hourly by `herdr_session_snapshot.sh` as the `grid` family (`herdr-*-NNcells-grid.json` on the backup server, `cli-herdr.md`); restore = copy the newest over the live file, the running grid reloads it.
- The first run and every `=` reorder herdr to match the file; a fresh file is seeded from herdr, so the first run moves nothing.
- A session resumed BY HAND into a new tab, or a tab dragged by hand, is absorbed on the next refresh: one cell per lineage, the live cell takes the parked twin's slot when both sit in the same row. herdr reports a moved pane's agent a beat after the move, so a cross-workspace drop polls for it before it refreshes.
- Reordering only ever moves a tab to an EARLIER index, which sidesteps `tab.move`'s pre-removal counting (`cli-herdr.md`).

## Decided
- One picker, workspace 0 tab 0; every workspace is a row, every tab a cell, arrow keys move, Enter opens.
- Every herdr tab has a cell. A session tab keeps its cell when closed (parked, `P`); a bare-shell tab's cell goes with the tab.
- A cell points at a session LINEAGE and opens its highest-numbered member, so `/successor` never breaks a cell. One cell per lineage.
- Order is STORED in the grid's own file, seeded from herdr, never re-derived — parked cells have no herdr position and arrow-key muscle memory needs one.
- Glyphs and colors are herdr's own sidebar's for live cells (yellow filled working; green filled done — finished and not yet looked at; green hollow idle — looked at since, so both greens wait for input; red blocked); `P` parked; dim mark for a shell tab.
- The detail pane shows title, description, lineage position, transcript size and last activity — size because opening an 18 MB session is not instant.
- No auto-park. Parking is manual: close the tab, or `p` in the grid. A "parking exercise" is the operator sweeping the list when the machine feels heavy.
- Forget applies to parked cells only; a live tab always has a cell. No grid verb deletes a transcript.
- Truth split: herdr answers what is live; the grid file answers parked cells, order, descriptions. Never both for one fact.
- Backed up as its own family by `herdr_session_snapshot.sh`, alongside layout, agents, config and tabstore.
- Layout: the grid's order PREVAILS. When the grid is opened, and on an explicit key, it moves herdr tabs to match its own data; never on the background timer, so it cannot fight a hand-drag in progress. To change an order, change it in the grid. Within a workspace that is `tab.move` (socket only, id kept). Across workspaces the PANE moves and herdr builds a NEW tab with a new id — the grid rewrites its own row at once; the tab store's row is re-recorded by the per-minute cron (`cli-herdr.md`, "A tab that MOVES loses its row").
- Description = prime directive. Read from the lineage store, fall back to the title. No separate description store, so the grid file holds only order and parked cells.
- Three names, not one. The herdr tab LABEL is short ("MANAGE 08"); the session TITLE is long ("20260406 1️⃣ AI 🧐 MANAGE Claude Code Sessions 08"); the prime directive is the description. The grid row shows glyphs only; the detail pane shows all three. `r` renames the tab label. The label follows herdr while a tab is live (a hand rename in herdr sticks) and is captured into the grid file at park time, since a parked cell has no herdr tab to hold it.
- `n` — new session in the selected row's workspace. Two bottom-line prompts: the tab label (required; Esc cancels) and a few words for its first prompt (optional). The session starts through `herdr_session_manage.sh start` with the account of the cell under the cursor (a neighbor is usually the same kind of work; personal when none is recorded), default model and effort. The words go out as the first prompt, quoted, with an instruction to propose a long title, a prime directive and a done_when and set nothing until John approves — the words are his, the titling is the session's to draft and his to approve, so the never-rename-without-him rule holds. A closed workspace row is rebuilt first, as Enter does. The cursor stays in the grid on the new cell; Enter goes there. Refused on the grid's own row. If the first prompt could not be delivered the message says so and the session still exists. If `start` itself reports failure, the message is the manager's LAST output line (a raw multi-line tail once reached the bottom row and killed the grid, since curses refuses a newline there), the session may still exist — the tab is real, the report was not — and the rebuilt workspace's empty root tab is closed when the manager got as far as its own tab. Keys typed during the 10-30 s wait are dropped, not replayed into the grid.
- Reordering: `m` grabs the selected cell (status line reads MOVE), arrows carry it, `m` or Enter drops it, Esc cancels. Left/right within a row is a herdr `tab.move`; up/down carries it to another workspace, which is a pane move. A parked cell moves in the grid file only. Shift+arrow as a modeless shortcut if the terminal delivers those keys — the build tests that, it is not promised.

## Detection — nothing new was built
- `herdr api snapshot` lists every workspace, tab, pane, agent kind, session id and agent status; measured 46 ms. The grid pulls it on open and on a timer while open.
- `dotfiles/.claude/hooks/record-herdr-tab.sh` (SessionStart) writes tab → session into `~/.claude/state/state_claude_session_herdr_tabs.json` within 3 s of any Claude session starting in a herdr pane, grid open or not.
- `herdr_session_record_live.sh` (cron, every minute) catches tabs whose session moved.
- Tab ids are never reused and survive a server restart (measured, `cli-herdr.md`), so a tab id is a safe key; a parked cell's tab id is simply stale until it is opened again.

## Open
- After a herdr restart the grid's pane is a bare shell until someone runs `hg`; nothing runs it automatically. `hg run` draws the grid in the CURRENT pane — it is what `hg` types into the grid's own pane, not a verb to reach for.
- The cursor survives a restart: on the 3 s idle tick and on `q` the grid writes the cell under the cursor (uuid, tab, workspace, column) to `~/.claude/state/state_claude_session_grid_cursor.json`, only when it moved; on start it puts the cursor back by uuid, else tab, else the same column of the same workspace row, else top-left. A sidecar rather than the grid file, so the hourly backup never copies the grid for a cursor move.
- `r` opens the rename line with the CURRENT label loaded, cursor at its end: backspace, ←/→, Home/End, ctrl-U clears, Enter accepts, Esc keeps the old label. Both it and the `n` prompts scroll a long entry so the cursor's neighborhood stays on the row; a dictated paragraph is fine, and Enter sends all of it.
- The footer is the status legend and the key list on one line when the pane is wide enough, else the legend on one line and the keys on the next; rows stop one line earlier to make room.
